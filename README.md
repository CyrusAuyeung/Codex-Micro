# Micro Windows

<img src="public/micro.svg" width="72" alt="Micro Windows 图标">

Codex Micro 复刻键盘的 Windows 桌面配置工具。普通模式将快捷键写入键盘，Codex 模式在电脑上执行按键、旋钮和摇杆操作。支持多套配置、快捷键录入、实时高亮和软件内更新。

[下载最新版](https://github.com/CyrusAuyeung/Codex-Micro/releases/latest) · [所有版本](https://github.com/CyrusAuyeung/Codex-Micro/releases) · [更新记录](CHANGELOG.md) · [反馈问题](https://github.com/CyrusAuyeung/Codex-Micro/issues/new/choose)

## 安装与启动

1. 在 Release 的 **Assets** 中下载 `Micro-Windows-版本号-Setup-x64.exe`。
2. 运行安装包，完成当前 Windows 用户的安装。
3. 从开始菜单或桌面快捷方式打开 **Micro Windows**，进入独立配置窗口。

适用系统：**Windows 10 2004 或更新版本 / Windows 11 x64**，使用 .NET Framework 4.8。轻量安装包自带 Node.js，窗口使用 Microsoft WebView2；电脑缺少 WebView2 时，安装程序会联网补装。安装完成后的键位配置无需互联网。

关闭窗口后程序留在系统托盘，单击托盘图标即可恢复窗口，右键选择“退出”可彻底退出。重复启动也会恢复已有窗口。

“关于”中的“开机启动”默认关闭。启用后静默进入托盘，恢复上次已保存的方案和 Windows 自定义启用状态；未连接键盘时在后台等待。录入、草稿和仅测试状态不会在重启后恢复。

发现新版时，“关于”旁会显示提示。点击 **下载更新**，在软件内查看进度；通过大小与 SHA-256 校验后，点击 **安装并重启**。软件会退出、覆盖安装并重新打开，已有配置、备份和开机启动选择会保留。下载可取消或重试，有草稿或操作未完成时不会开始安装。便携或开发目录需先使用安装包安装。

适用键盘：同款 Codex Micro 复刻版，顶部旋钮与摇杆、13 颗按键，底排为触摸点和三颗并排小键。

## 两种配置方式

| | 普通模式 · 键盘执行 | Codex 模式 · 电脑执行 |
|---|---|---|
| 配置时连接 | `Codex Micro Config` Wi-Fi | 蓝牙 `Codex Micro` |
| 使用时模式 | 蓝灯普通模式，蓝牙 `Codex Micro KB` | 青灯 Codex 模式 |
| 保存修改 | 保存到当前 Windows 用户的本地配置 | 保存到当前 Windows 用户的本地配置 |
| 让配置生效 | 通过配置热点“写入键盘” | 启用 Windows 自定义 |
| 程序运行要求 | 写入并核对后可以退出 | 保留托盘程序运行，窗口可以关闭 |
| 配置内容 | 固件开放的普通键位与旋钮按下 | 按键、旋钮和摇杆上报的动作 |

## 将快捷键保存进键盘

1. 长按左下触摸点，灯变红时松开，进入 **Config 配置模式**。
2. 让电脑连接 **Codex Micro Config** 配置热点。
3. 在程序的“普通模式”页点击 **读取键盘**，或选择已有的本地配置。
4. 在俯视图中选择实体按键，使用预设、手动选择或 **录入组合键** 设置快捷键。
5. 点击 **保存修改** 保存本地配置，再点击 **写入键盘**，查看预览并确认。程序会备份写入前的键盘配置；未配置的位置沿用键盘当前值。
6. 按页面提示重新读取并核对。键盘若重启，需要重新进入 Config 模式并连接热点。
7. 核对成功后回到蓝灯普通模式，通过蓝牙连接 **Codex Micro KB** 使用。

两个模式都支持本地配置管理，可离线编辑、新建、切换、导入导出和备份恢复。普通模式兼容旧版键位 JSON 与草稿文件，导入后作为新配置出现，选中再写入键盘即可。连接说明和诊断分别位于顶部的 **帮助** 与 **连接设置**。

## 快捷键录入

点击“录入组合键”，出现“请按下组合键”后试按。录入期间会实时显示组合，并拦截本次快捷键。

- **替换主键**：按 `Alt + A`，松开 A 时仍显示 `Alt + A`；保持 Alt，再按 B，显示更新为 `Alt + B`。
- **单个或多个修饰键**：支持 `Alt`、`Ctrl + Alt`，主键可以为空。
- **反复试按**：全部松开后保留候选组合，可以继续试按；点击 **使用此组合** 才完成录入。
- **调整修饰键**：修改修饰键后重新按主键，得到新的完整组合。松开的先后顺序不会拆散已经录入的组合。

## Codex 本机改键与旋钮

1. 切到青灯 Codex 模式，在 Windows 蓝牙设置中连接 **Codex Micro**。
2. 打开“Codex 模式”页，选择实体位置，点击识别并操作对应按键。
3. 选择要执行的 Windows 功能或录入组合键，点击“保存修改”。设备就绪时会同时启用 Windows 自定义；离线保存会保留启用状态。

旋钮按下、顺时针、逆时针以及摇杆方向可分别识别和绑定，具体取决于键盘在 Codex 模式下上报的动作。支持组合键、音量、媒体控制以及纵向/横向滚动。滚动步长为 1–10 个滚轮单位；旋钮与摇杆可以分别反转方向。摇杆触发/回中阈值随方案保存，默认 0.55/0.30；长拨连发默认关闭，可设置首次延迟与间隔。

启用 Windows 自定义后，实体输入会实时高亮。“仅测试”只显示输入，不执行本程序的快捷键、媒体或滚动动作；隐藏窗口、切换页面/方案或断连后自动结束。Windows 自定义和 Codex 默认控制共用 HID 通道，需切换使用；若 Windows 提示设备被占用，请先退出或暂停另一控制程序。

## 配置方案与设备信息

两个页面左上角都可切换配置，“管理配置”共用新建、复制、重命名、删除、导入导出及备份恢复操作。导入默认新增配置，重名自动区分；导出和备份包含已保存配置。切换前有草稿时可选择保存、放弃或继续编辑。普通与 Codex 配置分开存储，避免把电脑执行动作误写入键盘。旧版 `bindings.json` 首次启动时先备份，再迁移为“当前配置”；原有键位、设备关联和启用状态保留。普通模式首次从上次读取的键盘配置初始化。

切换模式在同一窗口内完成，保留键位选择和读取状态。两边统一使用“重置此键”“撤销修改”“保存修改”：重置只修改草稿，撤销恢复本地已保存配置，保存不会自动发起普通模式的设备写入。

两个页面右上角共用设备信息入口。普通蓝牙模式可读取电量；Codex 模式启用 Windows 自定义或仅测试时，还可读取固件版本与充电状态。缺失信息显示同一把键盘的历史结果，并标注“上次读取”和时间；识别到不同或多个设备时不混用缓存。

固件版本按设备返回值显示；V1.2 Beta 仍可能返回 `0.1.0-esp32s3`。两个模式的电量接口可能返回不同数值，程序显示实际读取结果。

## 常见问题

**为什么普通模式没有旋钮顺逆时针的保存项？**

当前固件的普通键位接口提供 16 个配置位，界面按 13 颗实体按键和旋钮按下呈现，其余两项在“其他配置位”中查看。旋转方向和摇杆方向需要固件提供对应的写入接口；目前可在 Codex 本机改键中配置。

**为什么没有 Fn 录入？**

多数键盘的 Fn 由键盘固件处理，Windows 收不到独立按键事件。可录入 Ctrl、Shift、Alt、Win 及其组合；系统保留的 `Ctrl + Alt + Delete` 也无法由普通应用拦截。

**无法读取或写入键盘？**

确认键盘处于红灯 Config 模式，电脑已连接 **Codex Micro Config**，再点击 **连接设置 → 检查连接**。若无法获取网络地址，可按提示临时修复连接；此操作需要管理员权限。

**是否需要一直开着窗口？**

普通模式的设置经写入和核对后保存在键盘中，程序可以退出。Codex 本机改键由托盘程序执行，关闭窗口后仍可使用，退出托盘程序后停止。

**设置和备份在哪里？**

`%LOCALAPPDATA%\Micro Windows\` 中的 `bindings.json` 与 `backups` 保存 Codex 配置及备份；`ordinary-profiles.json` 与 `ordinary-backups` 保存普通模式本地配置及备份；`device-config\backups` 保存键盘写入前的配置。下载的更新包位于 `updates`，安装结果写入 `updates\install-result.json`。排查启动问题可查看 `panel.log`。

## 源码与构建

JavaScript 服务使用 Node.js 内置模块，桌面窗口使用 C# WinForms 与 WebView2。准备 Windows x64、.NET Framework 4.8、Windows 10/11 SDK（用于蓝牙元数据）和 Python 3.11+，在仓库根目录执行：

```powershell
python build.py
.\runtime\node.exe scripts/test.mjs
python scripts/package.py
```

构建脚本下载并校验指定版本的 Node.js 与 WebView2 SDK，再编译六个 EXE 并运行原生自检。打包使用 Inno Setup 7.1.0，首次打包时准备编译器。已有同版本 Node.js 可通过环境变量 `MICRO_NODE_SOURCE` 指定文件，仍会校验 SHA-256。

安装包与 `SHA256SUMS.txt` 位于 `.build/release/`。`python scripts/verify-package.py` 在独立目录验证安装、覆盖更新、更新辅助程序和卸载，并检查配置保留；检测到当前用户已安装本程序时会停止，适合在干净测试用户或 CI 中执行。每次发布需同时上传安装包和 `SHA256SUMS.txt`；程序优先使用 GitHub 资产摘要，缺失时使用同版校验文件。

界面测试使用 Playwright 和模拟设备，覆盖首屏布局、快捷键录入、保存回读及桌面窗口生命周期。运行方式见 [开发与发布](CONTRIBUTING.md)。

| 路径 | 内容 |
|---|---|
| `public/` | 两种配置页面、实体布局和录入交互 |
| `server.mjs`、其他根目录 `.mjs` | 本地服务、设备映射、输入和网络适配 |
| `native/` | 启动器、HID、网络和组合键拦截辅助程序 |
| `assets/` | Windows 图标与图标生成脚本 |
| `installer/` | 当前用户安装、WebView2 补装和卸载流程 |
| `tests/` | 单元测试、接口测试和模拟设备 |
| `scripts/` | 运行时准备、版本检查、打包和发布工具 |
| `.github/workflows/` | Windows 持续集成与手动发布流程 |

## 版本与发布

历史 **1.x** 的源码快照和便携 ZIP 保留在对应 `v` 标签与 Release 中。从 **2.0.0** 起提供独立桌面窗口和 EXE 安装包。`main` 用于后续开发。

新版本通过 GitHub Actions 的 **Release → Run workflow** 手动发布。填写与源码一致的版本号，流程完成构建、测试、打包和核验后创建标签并发布下载包。具体修改与发布步骤见 [CONTRIBUTING.md](CONTRIBUTING.md)。
